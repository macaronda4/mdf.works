スクリーンショットはPNG、写真はJPEG
画像形式の選び方

スクリーンショットを JPEG で保存すると、文字のまわりが薄く汚れます。 設定を最高画質にしても、完全には消えません。 画質の良し悪しではなく、JPEG が想定していない絵を渡しているからです。 何がどう捨てられているのかを見ると、使い分けの基準がはっきりします。

    まず結論

    中身選ぶもの理由
    スクリーンショット、文字、図、線画PNG1ピクセルも変えずに保存できる
    写真JPEG（Web なら WebP / AVIF）見て分からない情報を捨てて小さくできる
    透過が必要PNG / WebP / AVIFJPEG には透過が無い
    ロゴ、アイコン、グラフSVG拡大しても粗くならない

    以下はこの表の理由の説明です。「なぜそうなるのか」が分かると、 迷ったときに自分で判断できるようになります。

    可逆と非可逆 — この区別がすべての土台

    画像の圧縮方式は、大きく2種類に分かれます。

    • 可逆圧縮（PNG など）：復元すると元と完全に一致します。「同じ色が続く部分をまとめる」といった、情報を捨てない工夫で縮めます。
    • 非可逆圧縮（JPEG など）：情報を捨てて縮めます。捨てた分は永久に戻りません。かわりに、はるかに小さくなります。

    非可逆が乱暴に思えるかもしれませんが、写真では非常に理にかなっています。 人間の目は明るさの変化に敏感で、色の細かい変化には鈍い。 その性質を利用して、気づかれない情報から優先的に捨てているわけです。

    問題は、その「気づかれない」という前提が、文字では崩れることです。

    JPEG が文字に弱い、2つの理由

    1. 8×8のブロックごとに処理している

    JPEG は画像を 8×8 ピクセルの区画に分け、区画ごとに 「なだらかな変化」と「細かい変化」に分解して、細かいほうを削ります。

    写真の中身はたいていなだらかなので、これがよく効きます。 ところが文字の輪郭は白から黒へ1ピクセルで飛ぶ、極端に細かい変化です。 これを少ない情報で表そうとすると、境界の周りに本来なかった濃淡の波が出ます。 文字のまわりがぼんやり汚れて見えるのは、この波です。

    2. 色の情報を間引いている

    多くの JPEG は、明るさは全ピクセル分保つ一方、 色は縦横それぞれ半分に間引いて記録します（色の情報量は4分の1）。 写真ではまず気づきません。

    しかし、赤い文字や青いリンクの文字では話が変わります。 色の境界が半分の粗さになるため、文字のふちに違う色がにじみます。 Discord のような濃い背景に載った色つきの名前は、特に目立ちます。

    だから品質を上げても限界があります。 品質設定は「どれだけ細かい変化を残すか」の調整で、 ブロック単位で処理することと色を間引くことは、そのままです。 文字を含む画像は、最初から可逆で保存するのが唯一の解です。

    PNG の得意と不得意

    PNG は可逆なので、スクリーンショットの文字は保存しても1ピクセルも変わりません。 透過も扱えます。スクリーンショットの標準的な保存形式になっているのは、この2点が理由です。

    弱点は写真です。写真は隣り合うピクセルがわずかずつ違うので、 「同じ色をまとめる」という手が効きません。結果として、 同じ写真が JPEG の5倍から10倍の大きさになることも珍しくありません。

    PNG を小さくする方法： 色数が少ない画像（図、単色背景のスクリーンショット）なら、 使う色を256色までに絞る形式に変換すると大幅に小さくなります。 文字はくっきり保たれます。写真が含まれる場合は色が破綻するので使えません。

    WebP と AVIF は何が違うのか

    どちらも新しい形式で、可逆と非可逆の両方に対応し、透過も扱えます。 JPEG と PNG の役割を1つで兼ねられる、という点がまず大きな違いです。

    JPEGPNGWebPAVIF
    可逆で保存できないできるできるできる
    透過ないあるあるある
    アニメーションないない（APNG は可）あるある
    同じ見た目での大きさ基準写真では大きい3割ほど小さいさらに小さい
    変換にかかる時間速い速いやや遅い遅い

    AVIF は特に、強く圧縮したときの粘りが違います。 JPEG なら破綻するような小さいサイズでも、それなりに見える絵を保ちます。 かわりに変換に時間がかかるため、その場で保存する用途より、 あらかじめ用意しておく Web 配信向きです。

    ただし、新しい形式は「渡した相手が開けるか」が付いて回ります。 主要なブラウザは対応済みですが、古い端末のアプリ、業務用のシステム、 印刷所への入稿などでは、いまでも JPEG か PNG が確実です。 人に渡すファイルは保守的に、自分のサイトに置くものは新しい形式で。 これが現実的な線引きだと思います。

    よくある勘違い

    JPEG を PNG に変換すれば画質が戻る

    戻りません。捨てられた情報は、どの形式に変換しても復元されません。 できるのは「これ以上劣化させない」ことだけです。 にじんだ文字は、にじんだまま可逆で保存されます。ファイルは無駄に大きくなります。

    何度保存しても同じ

    非可逆形式では、保存するたびに劣化が積み上がります。 JPEG を開いて少し書き込み、また JPEG で保存する。これを繰り返すと、 元は綺麗だった画像がじわじわ崩れていきます。

    作業中は可逆形式で持っておき、非可逆にするのは最後の1回だけにするのが基本です。

    透過 PNG を JPEG にしても平気

    JPEG に透過はないので、透明だった部分は黒や白で塗られます。 ロゴを配ったら背景が真っ黒になっていた、という事故はこれです。

    形式の選択は、プライバシーにも関わる

    カメラで撮った JPEG には、Exif と呼ばれる付随情報が入ります。 撮影日時、カメラの機種、設定、そして撮影場所の位置情報が含まれることがあります。 画像を見ただけでは分かりませんが、ファイルの中には残っています。

    画像を再び保存し直すと、この情報は多くの場合引き継がれずに消えます。 副作用として都合が良い動きですが、確実だと思い込むのは危険です。 アプリによっては意図的に引き継ぐものもあります。

    公開するつもりの写真なら、位置情報が残っていないかを一度確認しておくと安全です。 スクリーンショットには通常 Exif は入りませんが、 画面の中に写り込むものは別の問題として残ります。

    まとめ

    • JPEG は「人が気づかない情報を捨てる」方式。文字ではその前提が崩れる
    • にじみの正体は8×8ブロック単位の処理と色の間引き。品質設定では消えない
    • 文字が含まれるなら可逆形式（PNG）。写真なら非可逆で十分
    • WebP と AVIF は両方できる。自分のサイトには新形式、人に渡すなら従来形式
    • 変換で画質は戻らない。非可逆にするのは最後の1回だけ

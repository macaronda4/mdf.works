ダークモードは色を反転するのではない
実装して分かったこと

OS の設定に合わせるだけなら CSS 一行で済みます。利用者が上書きできるようにした瞬間に、話が変わりました。指定の優先順位、描画前のちらつき、そして配色そのものの作り直し。順に踏んだところを書きます。

開発 2026年8月30日 約5分で読めます

目次

    一行で済む版

    OS の設定にただ従うだけなら、これで終わりです。

    端末が暗い配色を望んでいるかどうかは prefers-color-scheme で分かります。 色を変数に逃がしておいて、その中でだけ値を差し替えれば、全体の見た目が切り替わります。 ここまでは簡単でした。

    上書きを許した瞬間に増える面倒

    問題は「OS は暗いけれど、このサイトは明るく読みたい」に応えたくなったときです。 切替ボタンを置くと、状態が3つになります。

    1. 何も選んでいない OS の設定に従います。初めて来た人はここにいます。
    2. 明るいほうを選んだ OS が暗くても、明るく表示します。
    3. 暗いほうを選んだ OS が明るくても、暗く表示します。

    選択は <html> の属性として持たせました。 何も選んでいなければ属性そのものが無い、という形です。 すると CSS はこう並びます。

    書く場所受け持つ状態
    素の :root明るい配色を、すべての既定値として置く
    OS が暗いとき、かつ明るいを選んでいないとき暗い配色に差し替える
    暗いを選んだとき暗い配色に差し替える

    真ん中の「かつ、明るいを選んでいないとき」が要ります。 これを書き忘れると、OS が暗い人が明るいほうを選んでも暗いままになります。 自分で切り替えたのに何も起きない、といういちばん困る壊れ方をするので、 ここは実際に OS 側を暗くして確かめました。

    暗い配色の中身を2か所に書くことになります。 片方だけ直して、もう片方が古いままになるのがこの構成の弱点です。 色は必ず変数にして、値の定義を1か所ずつに閉じ込めておくと事故が減ります。

    一瞬だけ明るくなる

    切替を入れた直後、暗いテーマを選んでいる人の画面で、 読み込みのたびに一瞬だけ白い画面が出るようになりました。

    原因は順番です。選択は保存領域から読み出す必要がありますが、 読み出して属性を付けるコードがページの後ろにあると、 ブラウザはその前に一度描画を済ませてしまいます。 属性が付く前の状態、つまり既定の明るい配色が、一瞬だけ見えます。

    直しかたは単純で、保存された選択を読んで属性を付けるだけの短いコードを、 本文より前に、同期的に置くことです。 ここだけは意図的に描画を止めます。数行なので体感には影響しません。

    この場所のコードは失敗しても止まらないように書いてください。 保存領域は、設定によっては読もうとしただけで例外を投げます。 ここで例外が飛ぶと、後続のスクリプトごと巻き添えになります。 読み書きは短く囲って、失敗したら「何も選んでいない」として扱えば十分です。

    アドレスバーの色も変わる

    スマートフォンでは、ブラウザの上下の帯にページ側から色を指定できます。 切替のときにここも合わせて更新しないと、 本文だけ暗くなって、帯だけ明るいままという半端な見た目になります。 最初は完全に見落としていて、手元の端末で気づきました。

    そして本題。色は反転させない

    明るいほうの配色を作ってから、それを反転させて暗いほうにしようとしました。うまくいきません。

    黒地に白は、まぶしい

    純粋な黒の上に純粋な白を置くと、コントラストが強すぎて文字が滲んで見えます。 暗い部屋では特にきつくなります。 実際には背景を少し持ち上げ、文字を少し落とすほうが読みやすくなります。

    影が効かない

    明るい配色では、影で要素の浮き沈みを表現できます。 暗い配色では影がほとんど見えません。 代わりに、面の明るさそのものを段階にして、奥行きを作り直す必要があります。 背景・面・沈んだ面、というように名前を付けた変数にしておくと、両方の配色で同じ意味を保てます。

    同じ色が、同じ強さに見えない

    アクセントに使っていた濃いオレンジは、暗い背景の上ではくすんで沈みました。 暗いほうでは明度を上げた別の値を当てています。 同じ色名で管理していても、実際の値は両者で違います。

    確かめかた： 文字と背景の組み合わせを全部書き出して、コントラスト比を測ってください。 本文・補助的な文字・リンク・ボタンの中の文字・枠線と、意外に数があります。 片方の配色だけ基準を満たしていて、もう片方が足りていない、というのがよく起きます。 このサイトも一度そうなっていて、あとから配色をまとめて見直しました。

    入れてよかったか

    よかったと思っています。ただし、費用はCSS ではなく確認の手間のほうに出ます。 色を1つ足すたびに、両方の配色で見え方を確かめることになります。 最初から変数で作っておくと、この確認がだいぶ楽になります。

    まとめ

    • OS に従うだけなら簡単。上書きを許すと、指定が三段構えになる
    • 「明るいを選んでいないとき」の条件を落とすと、切り替えても何も起きない
    • 描画前に選択を当てないと一瞬だけ明るい画面が見える
    • 保存領域の読み書きは失敗しても止まらないように囲う
    • 暗い配色は反転ではなく作り直し。影が効かず、同じ色が同じ強さに見えない

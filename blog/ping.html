Ping はどこで生まれるのか
回線を速くしても下がらない理由

「1Gbps にしたのに Ping が変わらない」。当然です。 速度と遅延は別のものだからです。遅延がどこで何ミリ秒ずつ積まれているのかを、 いちばん下の物理法則から順に分解していきます。

    Ping とは往復にかかる時間

    Ping 値は、自分の端末からサーバーへ信号を送り、返事が戻ってくるまでの往復時間（RTT）です。 単位はミリ秒。1秒間にどれだけのデータを運べるか（帯域）とは、まったく別の指標です。

    よく使われるたとえですが、帯域は道路の車線数、遅延は目的地までの距離だと考えると分かりやすいと思います。 車線を増やせば一度に運べる量は増えますが、片道の所要時間は1秒も短くなりません。 回線を 100Mbps から 1Gbps に変えても Ping が変わらないのは、車線を増やしただけだからです。

    まず、絶対に縮まない部分がある

    光ファイバーの中を光が進む速度は、真空中の約 3 分の 2、およそ 秒速 20 万キロメートルです。 ガラスの屈折率のぶん遅くなります。ここは技術ではどうにもなりません。

    距離が決まれば、往復にかかる最低時間が計算できます。 実際のケーブルは直線ではなく、経路は直線距離の 1.3〜1.5 倍ほどになるのが普通なので、 それも見込んだ概算が次の表です。

    接続先おおよその直線距離物理的な下限（往復）現実によく見る値
    同じ都市の中〜30 km1 ms 未満3〜10 ms
    東京 ↔ 大阪約 400 km約 5 ms10〜20 ms
    東京 ↔ シンガポール約 5,300 km約 70 ms80〜120 ms
    東京 ↔ 米国西海岸約 8,300 km約 110 ms110〜160 ms
    東京 ↔ 欧州約 9,500 km約 125 ms220〜280 ms

    欧州だけ下限との差が大きいのは、日本と欧州を直接つなぐ海底ケーブルが限られており、 多くの経路がいったん北米や東南アジアを経由するためです。地理的な距離より、実際に通る道のりが長くなります。

    ここから読み取れること： 北米サーバーに繋いで Ping 120ms なら、それはほぼ理論値に近い良好な接続です。 改善の余地はありません。この場合にやるべきは回線の見直しではなく、 近いサーバーを選ぶことです。

    その上に積まれていくもの

    物理的な下限に対して、現実の Ping はもう少し大きくなります。差はどこから来るのか。

    1. 中継機器での処理（1ホップあたり 0.1〜数 ms）

    経路上のルーターは、パケットを受け取って宛先を判断し、次へ送り出します。 1台あたりの処理はごくわずかですが、家から目的地まで 10〜20 台を経由するのが普通なので、 積み上がると数ミリ秒になります。tracert（Windows）や traceroute で経路と各段の時間を見られます。

    2. アクセス回線の方式（0〜数十 ms）

    家から最初の設備までの区間です。ここは方式によって差が大きいところです。

    • 光回線：数 ms 程度。現状もっとも安定します。
    • ケーブルテレビ回線：光よりやや大きく、上り方向で差が出やすい傾向があります。
    • モバイル回線：無線区間の制御があるぶん上乗せされます。世代が新しいほど小さくなります。
    • 衛星：静止軌道だと高度約 36,000km を往復するため、原理的に 500ms 前後。低軌道の方式なら大幅に短くなります。

    3. Wi-Fi（1〜数十 ms、しかも揺れる）

    無線は「電波が飛ぶ時間」が問題なのではありません。距離的にはごくわずかです。 効いてくるのは順番待ちです。無線は同じ帯域を全員で共有するため、 誰かが送信している間は待つ必要があります。電子レンジや隣家のルーターとも取り合いになります。

    その結果、平均値はさほど悪くなくてもばらつきが大きくなります。 2.4GHz 帯は混みやすく、5GHz 帯や 6GHz 帯のほうが安定します。 有線が使えるなら、迷わず有線にするのがいちばん効果的です。

    4. 混雑による待ち行列（0〜数百 ms）

    これが曲者です。回線が上限まで使われているとき、 送りきれないパケットはルーターの内部で順番待ちの列に並びます。 列が長いほど待ち時間が伸び、普段 20ms のところが数百 ms に跳ね上がることがあります。

    「家族が動画を見始めるとゲームがカクつく」のは、たいていこれです。 メモリが安くなって機器の待ち行列が大きく作られるようになった結果、 パケットを捨てずに溜め込みすぎて遅延が悪化する現象は バッファブロート（bufferbloat）と呼ばれ、広く知られています。

    対策として、待ち行列を賢く管理する仕組み（SQM、fq_codel など）を持つルーターがあります。 QoS 設定でゲーム機を優先する機能も、実質的には同じ狙いのものです。

    5. サーバー側の更新間隔（数 ms〜数十 ms）

    見落とされがちですが、ここも遅延です。 対戦ゲームのサーバーは、常に情報を流し続けているわけではなく、 1秒間に決まった回数だけ状況をまとめて送ります。この回数をティックレートと呼びます。

    ティックレート更新の間隔平均で上乗せされる遅延
    20 tick50 ms約 25 ms
    30 tick33 ms約 17 ms
    64 tick15.6 ms約 8 ms
    128 tick7.8 ms約 4 ms

    自分の操作がサーバーに届いても、次の更新のタイミングまでは反映されません。 待ち時間は 0 から更新間隔までばらつくので、平均するとその半分が上乗せされます。 これは自分側では一切改善できません。 同じ Ping なのにゲームによって手応えが違うのは、多くの場合この差です。

    実は体感を決めているのはジッター

    Ping が一定の 60ms であるより、20ms と 150ms を行き来するほうが、はるかに気持ち悪く感じます。 このばらつきをジッターと呼びます。

    理由は、ゲームが遅延を前提に作られているからです。 一定の遅れなら、それを見込んで表示を調整できます。 しかし到着時刻が予測できないと、補正が外れて敵が瞬間移動したように見えたり、 当たったはずの攻撃が無効になったりします。

    パケットロス（届かなかったパケット）も同様です。失われた分は、 再送を待つか、推測で埋めるしかありません。1〜2% でも体感は大きく崩れます。

    確かめかた： Windows なら ping -t 対戦相手のサーバー、Mac なら ping ホスト名 を数分流しっぱなしにして、 値が一定かどうかを見ます。平均値より最大値と最小値の開きに注目してください。 家族が動画を見ている時間帯にも試すと、混雑の影響が分かります。

    効く対策と、効かない対策

    効くもの（効果の大きい順）

    1. 近いサーバーを選ぶ 他のどの対策より効果が大きく、しかも無料です。地域選択があるゲームなら必ず確認してください。物理法則には勝てないので、距離を縮めるのが唯一の根本策です。
    2. 有線にする Wi-Fi 由来のばらつきが消えます。数値の平均以上に、体感が安定します。
    3. 同時に使う通信を減らす 大容量のダウンロード、クラウド同期、別端末の動画。待ち行列を作らないだけで跳ね上がりが止まります。
    4. ルーターの待ち行列管理を使う SQM や QoS。混雑時の跳ね上がりを抑えます。機器が対応している場合のみ。
    5. アクセス回線そのものを見直す モバイルやケーブルから光へ、といった変更。ここまでやって初めて数 ms 単位の改善です。

    効かない、または限定的なもの

    • 帯域だけを増やす契約変更：混雑が原因なら効きますが、距離由来の遅延には無関係です。
    • 「Ping を下げる」とうたう機器：中身は待ち行列の管理であることがほとんどです。混雑時には効き、それ以外では効きません。
    • ゲーム用 VPN：経由地が増えるぶん、原則として遅くなります。例外として、契約している回線の経路がたまたま遠回りな場合に短縮されることはあります。試す価値はあっても、当たり前に効くものではありません。
    • フレームレート向上：画面の反応は良くなりますが、通信の遅延とは別の話です。
    • ケーブルを高価なものに替える：規格を満たしていれば、それ以上速くはなりません。

    ゲーム側もかなり努力している

    遅延が消せない以上、ゲームは隠す方向で作られています。仕組みを知っておくと、 理不尽に見える現象の理由が分かります。

    • 先読み：ボタンを押した瞬間、サーバーの返事を待たずに手元で動かします。だから操作は軽く感じます。
    • 補正：ずれが判明したら、こっそり位置を合わせます。これが強く効くと、キャラクターが滑ったり瞬間移動して見えます。
    • 撃った時点への巻き戻し：撃った瞬間の相手の位置で判定します。撃たれた側から見ると「もう隠れていたのに当たった」となる原因がこれです。
    • ロールバック：格闘ゲームでよく使われます。相手の入力を予測して先に進め、実際の入力が届いた時点でずれていれば内部的に巻き戻して再計算します。遅延を待つ方式より、はるかに快適に遊べます。

    「自分の画面では当たっていたのに」という食い違いは、多くの場合バグではなく、 それぞれの画面が少し違う時刻の世界を映していることの結果です。

    まとめ

    • Ping は往復時間。帯域を増やしても下がりません
    • 距離ごとに物理的な下限があり、そこは技術では縮められない
    • その上に、機器・無線・混雑・サーバーの更新間隔が積み上がる
    • 体感を壊すのは平均値よりばらつき。数分間 ping を流して最大値と最小値を見る
    • 効果の順は 近いサーバー → 有線 → 同時通信を減らす。ここまでで大半は片付く

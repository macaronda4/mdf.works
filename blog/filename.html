ファイル名で困らないための決めごと
文字化けとパスの上限

ファイル名は最後に適当に付けるもの、という扱いになりがちです。ところが渡す・保管する・探すの全部に効いてきます。開けない、化ける、コピーできない。よくある詰まりかたと、それを避ける決めごとを並べます。

基本 2026年10月7日 約7分で読めます

目次

    使ってはいけない文字

    環境によって扱いが違うので、いちばん厳しい条件に合わせるのが安全です。

    文字起きること
    \ / : * ? " < > |Windows で使えません。共有すると保存できない
    先頭や末尾の空白見えないまま残り、検索で見つからなくなる
    末尾のピリオドWindows で消される、または保存できない
    半角スペース使えますが、URLになると %20 に化けて読みにくい
    絵文字や記号環境によって表示が崩れる。検索でも扱いにくい

    区切りに使うなら、ハイフンとアンダースコアが無難です。 空白の代わりにこれらを使うだけで、大半の問題が消えます。

    大文字と小文字の扱いも環境で違います。 Windows と macOS は既定で区別しませんが、 サーバー側では区別されるのが普通です。 Photo.JPG と photo.jpg を別物として置いていると、 手元では動いて公開すると壊れる、という現象が起きます。 小文字で統一しておくと、この種の事故が起きません。

    文字化けはどこで起きるのか

    名前が記号の羅列になる現象は、文字をどう数値に置き換えるかの取り決めが食い違ったときに起きます。

    いまはほとんどの環境が同じ方式に揃いましたが、 圧縮ファイルだけは別です。 古い形式には、その情報を記録する場所がありませんでした。 そのため、展開する側は推測することになります。 推測が外れると化けます。

    1. 相手の環境が分からないなら、名前を英数字にする いちばん確実です。日本語の名前が必要なら、圧縮ファイルの中ではなく、中に説明の文書を1つ入れるほうが安全です。
    2. 新しい形式を選ぶ 圧縮ソフトの設定に、文字の扱いを指定する項目があることがあります。相手も同じ系統のソフトを使うと分かっているなら、揃えられます。
    3. そもそも圧縮しない 数ファイルなら、まとめずにそのまま渡すほうが確実です。圧縮は分割送信のための手段であって、必須ではありません。

    パスには長さの上限がある

    ファイル名そのものではなく、先頭からの全体の長さに上限があります。 Windows では、既定でおよそ260文字です。

    深いフォルダの中に、長い名前のファイルを置くと超えます。 超えるとコピーできない、削除できない、開けないという状態になります。 しかも、エラーの内容から原因が分かりにくい。

    特に起きやすいのが、次の場面です。

    • クラウド同期のフォルダの中に、深い階層で保存している
    • 圧縮ファイルを、深い場所で展開した
    • フォルダ名にも日付や案件名を入れていて、階層ごとに長くなる
    • 共有されたフォルダを、自分の環境の深い場所に置いた
    対処として上限を緩める設定もありますが、 ソフトによっては対応していません。 設定を変えたのに一部のソフトだけ失敗する、という中途半端な状態になります。 階層を浅くするか、名前を短くするほうが確実です。

    日付と版の書き方

    ここを決めておくと、並べ替えと検索が一気に楽になります。

    日付は年から書く

    2026-08-31 の形にすると、 名前順に並べるだけで日付順になります。 8月31日 や 31-08-2026 では、そうなりません。 桁を揃えることも大切で、2026-8-3 だと 2026-8-31 の後ろに来ます。

    版は「最終」を使わない

    最終 の次に 最終2 が来て、 その次に 本当に最終 が来る。誰もが一度は通る道です。

    代わりに数字で通し番号を振るか、 日付を入れるほうが破綻しません。 v3 のような短い形でも、2026-08-31 でも構いません。 重要なのは次が何になるか、迷わず決められることです。

    実用的な形をひとつ挙げると、 2026-08-31_案件名_資料_v2.pdf のような並びです。 日付・対象・種類・版の順にすると、 日付順に並び、対象で絞り込め、種類で判別できます。 最初にこの順を決めておくだけで、あとの検索がまったく変わります。

    渡す前に整える

    1. 個人名や社内用の呼称を外す 田中さん修正版 のような名前は、そのまま相手に渡ります。ファイル名は本文より目に付きます。
    2. 作業用の記号を消す _修正前 _没 _使わない。中身と食い違っていると、余計な誤解を生みます。
    3. 使えない文字を置き換える 特に / と : は、日付や比率を書くときに使いがちです。
    4. 長すぎないか見る 目安として、ファイル名だけで50文字を超えたら見直します。相手がどこに保存するかは分かりません。
    5. 圧縮するなら、中身の名前も確認する 外側の名前だけ整えて、中が作業用のままということがよくあります。

    スクリーンショットの名前は、特に注意が要る

    自動で付く名前には、日時が入っています。 それだけなら害は小さいのですが、あとから自分で追記した名前が問題になります。

    Screenshot_2026-08-31_23-14_田中さんのDM.png のような名前を、 そのままアップロードしてしまう。 サービスによってはファイル名がそのまま公開されます。 画像の中身をどれだけ丁寧に隠しても、名前が残っていれば意味がありません。

    この点は公開前のチェックリストにも入れていますが、 本文の確認は念入りにするのに、名前は見落とすという偏りが起きやすい部分です。

    あとで探せる名前にする

    整理の話は、たいていフォルダをどう分けるかから始まります。 ただ実際には、名前のほうが効きます。 検索するとき、人はフォルダの階層をたどらずに名前で探すからです。

    1. 名前に、探すときの言葉を入れる 半年後の自分が何と打つかを想像します。案件名、相手先、書類の種類。フォルダ名でしか分からない情報は、名前にも入れておくと、どこにあっても見つかります。
    2. 略語を統一する 同じものを 見積 と 見積書 と estimate で書き分けると、検索に引っかかりません。どれでもよいので1つに決めることが大事です。
    3. 連番は桁を揃える 01 02 …10 と書きます。1 2 …10 だと、10 が 2 の前に来ます。3桁必要になりそうなら最初から3桁で。
    4. 中身を表す語を先に置かない すべての名前が 資料_ で始まると、並べ替えの意味がなくなります。先頭には、区別に役立つものを置きます。

    共有フォルダでの決めごと

    1人で使う分には自由でよいのですが、複数人になると衝突します。 細かい規則は守られないので、3つだけ決めるのが現実的でした。

    • 日付の書き方 — 年から、ハイフン区切り、桁を揃える。これだけで並べ替えが機能します
    • 版の付け方 — 「最終」を使わない。通し番号か日付にする
    • 作業中の目印 — 編集中のものが分かるようにします。先頭に記号を付けて、終わったら外す。誰かが開いている最中に別の人が保存する事故を減らせます
    規則を増やすほど守られなくなります。 3つを全員が守るほうが、10個を半分の人が守るより機能します。 そして決めたら、フォルダの中に短い説明を1つ置いておく。 新しく入った人が、聞かなくても分かる状態になります。

    拡張子を表示しておく

    最後にひとつ、設定の話をします。 多くの環境では、拡張子が既定で隠されています。 報告書.pdf が 報告書 としか表示されません。

    これが問題になるのは、見た目の名前と実際の種類が食い違うときです。 請求書.pdf.exe というファイルは、 拡張子が隠れていると 請求書.pdf に見えます。 文書だと思って開くと、実行してしまいます。

    拡張子は表示する設定にしてください。 エクスプローラーやファインダーの設定で切り替えられます。 普段の作業でも、種類がひと目で分かるので便利ですし、 種類を偽装する手口に対して、そのまま防御になります。 設定を1回変えるだけで、以降ずっと効きます。 家族の端末でも、同じ設定にしておく価値があります。

    ここまでの決めごとは、どれも一度覚えれば以降ずっと効く種類のものです。 日付の書き方を変えるのに費やす時間は数秒で、 その恩恵は数年続きます。整理術としては、かなり割のよい部類だと思います。

    まとめ

    • 使えない文字はいちばん厳しい環境に合わせる。区切りはハイフンかアンダースコア
    • 大文字と小文字はサーバー側では区別される。小文字で統一すると事故が減る
    • 圧縮ファイルの中の日本語名は化けやすい。英数字にするか、圧縮しない
    • パスには全体の上限がある。階層を浅くするか名前を短く
    • 日付は年から、桁を揃えて。名前順がそのまま日付順になる
    • 渡す前に個人名と作業用の記号を外す。名前は本文より目に付く

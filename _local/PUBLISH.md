# 毎日の記事公開

Windows タスク `mdf.works daily post` が毎日9:00に `_local/publish_daily.bat` を実行します。
2026-09-17に、予定時刻を逃した場合の後続実行と、失敗時15分間隔・3回の再試行を有効にしました。
現在のタスクは対話ログオン方式です。PCの起動と利用者のログイン、インターネット接続が必要です。
PCを停止したままでも公開されるクラウド処理ではありません。

通常の確認: `python -X utf8 _local/publish_next.py`
手動公開・再試行: `python -X utf8 _local/publish_next.py --write`
テスト: `python -X utf8 _local/test_publish_next.py`

- 原稿を番号順に1本選び、ページ・一覧・更新履歴・サイトマップ・OG画像を生成して検証します。
- コミットして origin/main に push し、反映先のコミット一致を確認します。
- 公開原稿を非公開の下書きリポジトリの履歴に保存してから、待ち行列から取り除いて push します。
- 日本時間の同日に新規公開済みなら、2本目は出しません。復旧作業中の原稿を優先します。
- 公開先での配信は GitHub 連携の Cloudflare Pages が担当します。push の成功は配信完了とは別です。

## 停止した場合

まず `_local/publish.log` の最後のエラーを確認してください。
`publish-state.json` は build / commit / push / archive の進行状態です。
削除すると重複や原稿の取り違えにつながるため、通常は残したまま同じ公開コマンドを再実行します。
`--no-push` は公開途中の状態と原稿を残し、次の `--write` で送信を再試行します。
公開中に原稿や生成物を編集した場合は、内容確認のため停止します。
状態ファイルなしで記事ファイルだけが存在する場合も、自動的に上書きしません。
既存の作業中の変更がある場合は、それを解決してから再実行してください。
`publish.lock` はOSの排他ロックであり、ファイルの存在自体は停止原因ではありません。

下書き・ログ・状態ファイル・yt-dlp関連は公開リポジトリの対象外です。
バックアップ用に追跡される `_local/*.py` 等は公開リポジトリから閲覧できます。
サイト配信でも取得できる現状のため `_headers` で noindex を指定していますが、これはアクセス制限ではありません。
機密情報をこれらの追跡ファイルに書かないでください。
